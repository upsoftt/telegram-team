# Сборка под iPhone

Собирается из оригинальных исходников `TelegramMessenger/Telegram-iOS`; патчи из
`patches/ios` накатываются поверх апстрима. Нужен Mac с Xcode — других вариантов нет,
сборка идёт через Bazel и подписывается системными средствами Apple.

## Что нужно

| Что | Зачем |
|---|---|
| macOS с Xcode | единственный способ собрать и подписать |
| Аккаунт разработчика Apple | сертификат распространения и профили подписи |
| Свой `api_id` и `api_hash` | без них сборка не поднимется |
| **40 ГБ свободного места** и около 9 ГБ под кеш Bazel | столько занимает сборка |

## Конфигурация

Скопируйте `scripts/mac/tgteam-configuration.template.json` в
`build-system/<своё имя>-configuration.json` внутри исходников Telegram-iOS и заполните:
идентификатор пакета, номер команды разработчика, ключ приложения и свою схему ссылок.
Файл содержит `api_hash`, поэтому в репозиторий он не кладётся — в шаблоне значения пустые.

Права, требующие особых разрешений Apple (Apple Pay, CarPlay, VoIP без ограничений,
привязанные домены), включаются только для официальных bundle id Telegram, а iCloud и Siri
выключаются в конфигурации — поэтому из возможностей достаточно общей группы приложений
(App Groups).

## Запуск

```sh
scripts/mac/run-build.sh <номер сборки>
```

Скрипт делает три вещи в правильном порядке: разблокирует связку ключей, гасит демон Bazel,
запускает сборку, — и пишет код возврата в файл-признак. Пароль связки он читает из
`~/.tgteam-build.env`; в репозитории пароля нет.

Полная команда, которую он выполняет:

```sh
python3 build-system/Make/Make.py --cacheDir="$HOME/telegram-bazel-cache" build \
  --configurationPath=build-system/<своё имя>-configuration.json \
  --buildNumber=<N> --configuration=release_arm64 \
  --codesigningInformationPath="$HOME/<каталог с профилями>"
```

Не запускать с `--xcodeManagedCodesigning`: этот режим не создаёт профили для расширений и
падает на `NotificationContent.mobileprovision`.

Сколько идёт: холодная сборка около 27 минут, после правки одного модуля — 10–20 минут.
Номер сборки обязан **расти**, иначе TestFlight не примет пакет.

## Проверка пакета до заливки

```sh
cd /tmp && rm -rf ipacheck && mkdir ipacheck && cd ipacheck
unzip -q <путь>/bazel-bin/Telegram/Telegram.ipa
APP=$(ls -d Payload/*.app)
plutil -p "$APP/Info.plist" | grep -E "CFBundleVersion|CFBundleIdentifier"
plutil -p "$APP/Info.plist" | grep -A6 CFBundleURLSchemes
codesign -dv "$APP" 2>&1 | grep -E "Identifier|TeamIdentifier"
```

Схемы ссылок проверять обязательно: они берутся из `Telegram/BUILD`, а не из
`Info.plist` в исходниках, и ошибка здесь не даёт ни предупреждения, ни сбоя — ссылка
просто молча не открывает приложение.

Картинки внутри бандла лежат в оптимизированном формате Apple и обычным просмотрщиком не
открываются: `sips -s format png <файл> --out <куда>`.

## Иконка приложения

У свежего Telegram-iOS основная иконка в формате Icon Composer (`icon.json` плюс SVG) —
растр туда не положить. Поэтому заводится классический
`<Своё>AppIcon.xcassets/AppIcon.appiconset`, на него смотрит `app_icons` в `Telegram/BUILD`.

Требования Apple, о которые легко споткнуться:

- **альфа-канал запрещён** — прозрачность надо свести на белое до уменьшения и писать PNG
  без канала прозрачности;
- **углы скруглять не надо** — маску накладывает система, в файле углы должны быть залиты;
- один неподходящий размер (например, 76×76@1x — это iPad с iOS до 10) валит весь каталог
  иконок целиком, и приложение остаётся вообще без иконки.

Иконка в списке «Оформление → Иконка приложения» берётся не из каталога, а из файлов
`<Имя>.alticon/<Имя>@2x.png` и `@3x.png` (120 и 180 точек).

## Грабли

| Выглядит как | Чем оказалось |
|---|---|
| Сборка падает, не найдя скачанный Bazel | контрольная сумма в `versions.json` записана для процессоров Apple; на Intel-машине файл считается «неправильным» и удаляется. Сумма подменяется на официальную для x86_64 |
| `ProcessEntitlementsFiles` падает на `application-groups` | возможность включена, но группа не привязана к идентификатору: в профиле пустой массив. Профиль фиксирует возможности на момент выпуска и сам не «дозаполняется» — после любого изменения возможностей его надо перевыпустить |
| `codesign`: `errSecInternalComponent` | связка ключей заперта и не отдаёт закрытый ключ. Разблокировать **до** старта демона Bazel: подпись идёт дочерним процессом демона и наследует его сессию |
| Лимит аккаунтов не поднялся, хотя константа изменена | числа продублированы прямо в коде трёх экранов. Проверять `grep -rn maximumAvailableAccounts` |
| Иконку приложения нельзя вернуть после выбора другой | первая плитка помечается основной только для сборок App Store (`isDefault: buildConfig.isAppStoreBuild`), а сброс делается только выбором основной |
| Ожидание конца сборки не срабатывает | `pgrep -f "Make.py"` находит сам себя, если строка есть в командной строке ждущего цикла. Ждать по файлу-признаку |
| Ссылка своей схемы не открывает приложение | список схем берётся из `Telegram/BUILD` (`UrlTypesInfoPlist`), а `Telegram/Telegram-iOS/Info.plist` в сборке Bazel не участвует вовсе |

## Раздача

Готовый `.ipa` заливается в TestFlight штатным `xcrun altool --upload-app`. Валидацию
(`--validate-app`) делать всегда: она ловит проблемы с иконками и правами до того, как
загрузка займёт номер сборки.

Внутренняя группа тестирования доступна сразу после обработки, но её участники должны быть
членами команды разработчика. Внешняя группа даёт публичную ссылку, по которой ставит кто
угодно, — но первую сборку в ней проверяет Apple.
