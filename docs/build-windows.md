# Сборка под Windows

Собирается из оригинальных исходников `telegramdesktop/tdesktop` — патчи из
`patches/desktop` накатываются поверх стабильного тега (сейчас `v7.1.1`). Скрипт
`scripts/build.ps1` делает всё сам: скачивает исходники, собирает библиотеки, настраивает
и компилирует клиент.

## Что нужно на машине

| Что | Зачем |
|---|---|
| Visual Studio 2022 с набором `v143`, MSVC 14.44 | требование самого Telegram Desktop |
| Windows SDK 10.0.26100.0 | то же |
| Python 3.10+, Git, CMake, Ninja | входят в состав Visual Studio |
| **60–80 ГБ свободного места** | столько занимают собранные библиотеки |
| Свой `api_id` и `api_hash` | без них Telegram Desktop не собирается вовсе |

NASM, Yasm, Perl и MSYS подготовительный скрипт Telegram ставит сам. Visual Studio 2026 не
нужна: генератор CMake не задаётся явно, набор инструментов указывается как `-T v143`.

Путь сборочного каталога держите **коротким** (`D:\Build\…`, а не глубоко вложенный):
C++-тулчейны упираются в предел длины пути Windows, и признак у этого обманчивый — CMake
сообщает «No CMAKE_C_COMPILER could be found» при полностью исправном компиляторе.

## Ключ приложения

```powershell
$env:TELEGRAM_API_ID = '<ваш api_id>'
$env:TELEGRAM_API_HASH = '<ваш api_hash>'
```

Ключ берётся бесплатно на [my.telegram.org](https://my.telegram.org) → «API development
tools». Скрипт подставляет его в момент запуска CMake; в репозиторий, в аргументы командной
строки и в лог сборки значение не попадает.

Тестовый ключ из документации Telegram (`17349`) не подойдёт: с ним пользователи получают
ошибку `API_ID_PUBLISHED_FLOOD`. Ключи официальных клиентов Telegram — тоже, вход не
сработает.

## Запуск

```powershell
powershell -File scripts\build.ps1 -All               # полный проход, идёт часы
powershell -File scripts\build.ps1 -Build -Deploy     # быстрая пересборка после правки
```

Этапы включаются по отдельности (`-Sources -Prepare -Configure -Build -Deploy`), потому что
подготовка библиотек идёт часы, а пересборка после правки — минуты. Параметры `-Root` и
`-InstallPath` задают, где собирать и куда выкладывать готовое.

Прерванная компиляция ничего не теряет: MSBuild продолжит с того файла, на котором
остановился, — повторять `-Prepare` и `-Configure` не нужно.

## Обновление на новую версию Telegram

1. `git fetch --tags`, затем `git merge <тег>` в своей ветке.
2. Развести конфликты. Их стабильно два: `version.h` — номер версии берётся апстримный, а
   имя приложения, имя файла и **GUID остаются свои** (по ним клиент находит свой каталог
   данных, чужой GUID означал бы пустой список аккаунтов); `application.cpp` — апстрим
   правит `checkStartUrls`, куда вставлено переключение аккаунта.
3. `git submodule update --init --recursive --depth 1` — новая версия приносит новые
   подмодули, без них конфигурация падает.
4. Перевыпустить патчи: merge-коммит `git format-patch` не выдаёт, поэтому патчи снимаются
   с временной ветки — `git checkout -B tmp <новый тег>`, `git cherry-pick` своих коммитов,
   `git format-patch <новый тег>..tmp`. Проверка: `git diff tmp <рабочая ветка>` пуст.
5. Собрать `-Prepare -Configure -Build`. Пересобираются только те библиотеки, чья версия
   изменилась.

## Грабли, каждая уже закрыта в `build.ps1`

| Выглядит как | Чем оказалось |
|---|---|
| Повреждённые объектные файлы libvpx (`LNK1136`), два десятка штук | `make -j` в libvpx запускает Debug и Release одного решения параллельно, обе конфигурации читают общий сгенерированный `vpx_config.asm`, и та, что не успела, получает файлы нулевой длины. Лечится последовательной сборкой |
| Те же `LNK1136` в другом месте | NASM 3.02 падает на флаге `-gcv8` |
| Сборка «зависла» | скрипт Telegram спрашивал про пересборку и ждал нажатия клавиши — нужен режим `silent` |
| `configure.bat` «не является командой» | в окружении задана `NoDefaultCurrentDirectoryInExePath`; вызывать полным путём |
| Ошибки `C1060`, `C1076`, `C3859` | нехватка памяти: MSBuild берёт по компилятору на ядро. Число процессов надо считать от **свободной** оперативной памяти, а не от числа ядер |
| Линковка `LNK2019` на `QBasicPlatformVulkanInstance` | на машине стоит Vulkan SDK, Qt собрался с Vulkan, а `Qt5VulkanSupport` не попал в список линковки |
| «Патч не лёг на тег» при целых патчах | `core.autocrlf=true` отдаёт `.patch` с переводами строк Windows, а `git am --keep-cr` эти CR сохраняет — контекст перестаёт совпадать. Закрыто файлом `.gitattributes` (`*.patch -text`) |

Общее правило по запуску сборочных `.ps1` в Windows PowerShell 5.1: не пропускать вывод
через `2>&1`, `*>&1` или `Tee-Object`. Каждая строка stderr от нативной программы
заворачивается в `ErrorRecord`, и при `$ErrorActionPreference='Stop'` скрипт падает на
безобидном предупреждении. Перенаправлять только stdout: `& script.ps1 > лог.txt`.

## После сборки

Готовый клиент — один файл `TelegramTeam.exe`, портативный: данные он держит в подпапке
`tdata` рядом с собой. Схемы ссылок забирает себе **та копия, которую запустили
последней**, — запуск из сборочного каталога уведёт ссылки туда.

Клиент должен работать с **обычными правами**. Запущенный «от имени администратора», он
становится недоступен для программ, работающих с обычными правами: Windows закрывает доступ
к каналу процесса с более высокими правами. Признак — вторая копия молча завершается с
кодом 0, будто всё удалось.
