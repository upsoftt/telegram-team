# Что изменено относительно оригинала

Разбор всех правок: что сделано, почему именно так и что это меняет для человека за
экраном. Сами изменения лежат в `patches/`: двенадцать патчей для Windows и семь для
iPhone, их можно применить к чистому апстриму командой `git am`.

Апстрим: [`telegramdesktop/tdesktop`](https://github.com/telegramdesktop/tdesktop) тег
`v7.3.1` и [`TelegramMessenger/Telegram-iOS`](https://github.com/TelegramMessenger/Telegram-iOS)
ветка `release-13.0.0`.
Правки — отдельные коммиты поверх тега, поэтому переход на новую версию Telegram делается
слиянием нового тега, а не переносом изменений руками.

## 1. Лимит аккаунтов — 50 вместо 3–6

**Зачем.** Официальный клиент держит три аккаунта, с подпиской Premium — четыре на iPhone
и шесть на компьютере. Когда рабочих аккаунтов больше, приходится выходить и заходить
заново, теряя историю сессий.

**Windows.** У Telegram Desktop предел задан одной константой
(`Main::Domain::kMaxAccounts` в `main/main_domain.h`) — её и достаточно поднять.

**iPhone.** Здесь константа `maximumNumberOfAccounts` есть, но три экрана — настройки
профиля, выход из аккаунта и удаление аккаунта — не читают её, а несут те же числа
прописанными в своём коде. Правка одной константы не даёт ничего: список аккаунтов
по-прежнему упирается в прежний предел, и понять это по интерфейсу нельзя — кнопка
«Добавить аккаунт» просто перестаёт появляться. Поэтому изменены все четыре места
(`AccountUtils.swift`, `PeerInfoScreenSettingsActions.swift`, `LogoutOptionsController.swift`,
`DeleteAccountOptionsController.swift`).

Сам Telegram ограничений на число одновременных аккаунтов в клиенте не накладывает —
предел придуман клиентом, а не сервером.

## 2. Открыть сообщение под нужным аккаунтом

**Зачем.** Внешняя программа (в нашем случае — служебный поиск по чатам) находит сообщение
и хочет открыть его в Telegram. Беда в том, что чат читается одним аккаунтом, а активен в
клиенте может быть любой другой: обычная `tg://`-ссылка откроет чат «не тем человеком»
либо не откроет вовсе, если у активного аккаунта нет доступа к этому чату.

**Как сделано.** Заведена своя схема ссылок `tgteam://` с дополнительным параметром
`account` — идентификатором пользователя Telegram:

```
tgteam://resolve?domain=имя_чата&post=1234&account=123456789
tgteam://privatepost?channel=1234567890&post=1234&account=123456789&text=текст+ответа
```

Клиент вырезает `account` из ссылки, находит среди подключённых аккаунтов тот, у которого
совпадает идентификатор, переключается на него и только потом открывает чат. Если такого
аккаунта в клиенте нет, ссылка открывается текущим аккаунтом: не открыть вовсе — хуже, а
молча ответить от чужого имени — недопустимо.

**Windows** (`core/application.cpp`): разбор добавлен в `switchAccountForStartUrls`, всё
остальное делает штатный путь `TryConvertUrlToLocal` → `openLocalUrl`.

**iPhone** (`AppDelegate.swift`): нужное переключение в апстриме уже есть — оно
используется для уведомлений (`openUrlWhenReady(accountId:url:)`), которые тоже должны
открываться нужным аккаунтом. Своего переключения писать не пришлось, достаточно вызвать
существующее. Важная деталь: точек входа две — тёплый старт идёт через `openUrl(url:)`, а
холодный (приложение было закрыто) минует его и приходит прямо из `launchOptions`. Разбор
добавлен в обе, иначе ссылка, поднявшая закрытое приложение, открывалась бы прежним
аккаунтом.

## 3. Текст ответа сразу в поле ввода

**Зачем.** Ссылка может нести не только «какое сообщение открыть», но и «что на него
ответить» — заготовку ответа, которую человек правит и отправляет.

**Windows** (`core/local_url_handlers.cpp`): у Telegram параметр `text` работает только для
ссылок вида `tg://resolve` — то есть для чатов с публичным именем. Ссылка на чат без
публичного имени идёт другим путём (`tg://privatepost`), где текст не читался вовсе: чат
открывался, поле ввода оставалось пустым. Теперь оба вида ссылок ведут себя одинаково.

**iPhone** (`UrlHandling.swift`, `OpenUrl.swift`): мешали две вещи сразу. Разбор ссылки нёс
**либо** номер сообщения, **либо** текст — для `t.me/чат/123?text=…` текст просто терялся;
заведены отдельные случаи разбора, которые несут и то, и другое, и открывают чат ответом на
нужное сообщение. Вторая: даже донесённый текст выбрасывался условием «только личные чаты»
(апстримное ограничение для ссылок `t.me/user?text=`) — оно снято.

## 4. Открытие обычных ссылок Telegram

**Windows** (`core/application.cpp`). За клиентом закрепляются три схемы: своя `tgteam://`
и общие `tg://`, `tonsite://`. У каждой свой ProgID (`tdesktopteam.<схема>`), поэтому
записи официального клиента не затираются — конкуренция идёт только за общий ключ реестра
`HKCU\Software\Classes\<схема>`.

Регистрация вынесена из ветки «версия сменилась» в безусловный вызов при каждом запуске:
официальный клиент записывает `tg://` на себя при каждом своём обновлении, и без этого
ссылки однажды молча уехали бы к нему. Запись дешёвая — значение сверяется и пишется
только при расхождении.

Кому принадлежит схема сейчас, видно так:

```powershell
(Get-ItemProperty 'HKCU:\Software\Classes\tg\shell\open\command').'(default)'
```

**iPhone** (`Telegram/BUILD`). Схема `tgteam` не попадала в приложение вовсе, и это
неочевидная ловушка сборки: список схем задаётся фрагментом `UrlTypesInfoPlist` в
`Telegram/BUILD`, а файл `Telegram/Telegram-iOS/Info.plist` в сборке Bazel не участвует.
Значение `app_specific_url_scheme` из конфигурации доходило только до кода, который ссылку
разбирает, — система же ссылку приложению не отдавала, и та молча не открывалась. При
добавлении пропускаются пустое значение и совпадения с уже перечисленными схемами: у всех
апстримных конфигураций `app_specific_url_scheme = "tg"`, и без проверки получился бы дубль.

Проверять по собранному пакету: `plutil -p Payload/*.app/Info.plist`.

**Чего на iPhone добиться нельзя.** Ссылки `https://t.me/…` из Safari к сторонней сборке не
придут никогда: привязку домена Apple выдаёт только официальным приложениям Telegram
(`associated_domains_fragment` в `Telegram/BUILD` включается лишь для их bundle id). И если
на устройстве стоит официальный Telegram, победителя за общую схему `tg://` выбирает
система — предсказуемо будет только без него.

## 5. Своё имя, свой каталог данных, своя иконка

**Windows** (`core/version.h`, `platform/win/windows_app_user_model_id.cpp`,
`Telegram/CMakeLists.txt`, `Resources/winrc/Telegram.rc`). Имя приложения, имя
исполняемого файла и GUID заменены на свои, плюс своя группа в панели задач. В свойствах
файла («Подробно» в проводнике) издателем указан не Telegram FZ-LLC, а сама эта сборка с
пометкой «unofficial build»: раздавать программу, которая называет своим издателем чужую
компанию, нельзя. Копирайт Telegram FZ-LLC и упоминание GPLv3 там остаются — этого требует
лицензия. Экземпляры Telegram разводятся по хэшу рабочего каталога,
поэтому эта сборка и официальный клиент не видят данных друг друга и спокойно работают
одновременно.

**iPhone** (`Telegram/BUILD`, `TgTeamAppIcon.xcassets`). Свой набор иконок: у свежего
Telegram-iOS основная иконка в формате Icon Composer (`icon.json` + SVG), растр туда не
положить, поэтому заведён классический `AppIcon.appiconset`, на который смотрит `app_icons`.
Заодно первая плитка в списке «Оформление → Иконка приложения» помечена основной: апстрим
помечает её только для сборок App Store, а без основной плитки выбранную иконку нельзя
вернуть обратно.

## 6. Ключ приложения не лежит в файле открытым текстом

**Зачем.** `api_id` и `api_hash` вкомпилированы в программу — иначе Telegram Desktop не
собирается вовсе, задать их при запуске нельзя. В готовом файле тридцатидвухзначный
`api_hash` находится обычным поиском строк за минуту, после чего чужие могут ходить в
Telegram под этим ключом. Наказывают в таком случае ключ, а ограничения (вплоть до
`API_ID_PUBLISHED_FLOOD`) получают пользователи сборки.

**Как сделано** (`config.h`, `Telegram/CMakeLists.txt`, `patches/desktop/0005` и `0007`).
Ключ попадает в компилятор уже перемешанным — параметром `TDESKTOP_API_HASH_SCRAMBLED`,
шестьдесят четыре шестнадцатеричных знака; перемешивает его сборочный скрипт. Обратное
преобразование делается один раз при первом обращении.

Первая попытка считать перемешивание прямо на этапе компиляции провалилась, и это стоит
знать тем, кто будет делать так же: MSVC всё равно кладёт исходный строковый литерал в
`.exe`, даже если тот используется только в `constexpr`-вычислении. После сборки ключ
находился в файле обычным поиском строк — поэтому исходного литерала в коде нет вовсе.

Если перемешанный ключ не задан, работает обычный путь апстрима: сборка «своими руками» по
инструкции из этого репозитория от правки не ломается.

**Чем это не является.** Защитой. Обратное преобразование лежит в том же файле, и человек
с отладчиком достанет ключ за полчаса — спрятать секрет внутри программы, которая сама им
пользуется, невозможно в принципе. Смысл только в том, чтобы ключ не собирался из чужих
сборок автоматически, поиском по образцу.

Правильный вывод из этого другой: **у раздаваемой сборки должен быть отдельный ключ**, не
тот, которым работают ваши собственные инструменты.

## 7. Закрепление чатов не режется подпиской

**Зачем.** Закреплённых чатов в основном списке официальный клиент даёт пять, с подпиской
Premium — десять; в папках соответственно сто и двести. Ограничение раздражает там, где
работа идёт из нескольких десятков рабочих чатов.

**Как сделано** (`data_premium_limits.cpp`). Клиент больше не выбирает между «обычным» и
«премиальным» пределом, а всегда берёт больший — для основного списка, папок, архива и
списка «Избранное». Кнопка «Закрепить» перестаёт быть серой раньше времени.

**Чего это не делает.** Предел ставит **сервер Telegram**, а не клиент: значения приходят
в настройках приложения (`dialogs_pinned_limit_default`, `dialog_filters_chats_limit_*` и
прочие), и запрос сверх серверного предела будет отклонён — правка снимает только
клиентскую заслонку. Практический итог: без Premium в основном списке по-прежнему пять
закреплённых, зато в каждой папке — сто, и клиент этому больше не мешает.

## 8. Сохранение и пересылка из каналов с запретом копирования

**Зачем.** Владелец канала с запретом копирования не может переслать собственный пост
своим сотрудникам: официальный клиент прячет кнопки «Переслать», «Копировать» и
«Сохранить как» от всех, включая создателя канала.

**Windows** (`data_peer.*`, `history_item.*`, `data_peer_values.cpp`, проверки кнопок в
окне чата, меню и просмотрщике; `patches/desktop/0009`–`0011`). У раздаваемой сборки
запрет снимается **только у администраторов** канала или группы: создатель либо админ
хотя бы с одним правом. Для своей команды сборка собирается с флагом
`TGTEAM_UNLOCK_PROTECTED` (`build.ps1 -UnlockProtected`), и тогда запрет снимается везде.
Флаг ставится на один файл `data_peer.cpp`, поэтому переключение между сборками
пересобирает один файл, а не весь клиент.

`allowsForwarding()` по-прежнему отдаёт настоящее значение с сервера: его читает окно
настроек канала, и подмена там выключила бы защиту у всех подписчиков при первом же
сохранении настроек. Кнопки смотрят на новый `allowsForwardingForMe()`.

Сервер Telegram защищённую пересылку отклоняет даже администратору, поэтому такое
сообщение уходит **копией**: вложения скачиваются в папку `protected_copies` внутри «Пути
для сохранения» из настроек (при пути по умолчанию рядом с данными клиента), загружаются
заново и удаляются, как только всё отправлено. Альбом остаётся альбомом, голосовое
голосовым, текст сохраняет оформление; строки «Переслано из» у копии нет.

**iPhone** (`PeerUtils.swift`, `MessageUtils.swift`, `PeersData.swift`,
`TgTeamProtectedCopy.swift` и соседи; `patches/ios/0005`). Сборка одна, запрет снят в любом
канале и группе. Копия встаёт в чат сразу и показывает ход загрузки, а вложение докачивается
с оригинала, когда загрузчику понадобятся байты. Окно настроек канала читает сам флаг, а не
подменённое значение, по той же причине, что и на Windows. Поэтому iPhone-сборки с этой
правкой раздаются только своей команде, а не по общей ссылке.

## 9. Код из уведомления копируется одним нажатием

**Зачем.** Код подтверждения приходит в Telegram сообщением, и чтобы его скопировать,
приходится открывать чат, искать сообщение и выделять цифры.

**Windows** (`window/notifications_manager*.cpp/.h`,
`platform/win/notifications_manager_win.cpp`, `window/window.style`;
`patches/desktop/0012`). Код — первый моноширинный фрагмент сообщения (до 64 знаков, в одну
строку) или код входа от самого Telegram. У всплывающего окна Telegram при наведении рядом с
«Ответить» появляется кнопка с самим кодом и значком копирования; нажатие кладёт код в буфер
обмена и закрывает уведомление, чат не открывается. Если обе кнопки не помещаются, не
заслоняя фото, остаётся только копирование. Код входа на кнопке не показывается (в тексте
он под спойлером), там написано «Копировать». У системных уведомлений Windows это кнопка
«Копировать 413477» в списке действий.

Код при нажатии берётся из сообщения заново, а не из текста уведомления: уведомление в
центре уведомлений может пережить блокировку паролем или правку сообщения. Если сообщение
отредактировали, пока уведомление на экране, подпись кнопки обновляется. В защищённых чатах
без снятого запрета кнопки нет, а при скрытом тексте уведомлений её нет вовсе.

## 10. Сториз под другими сториз не играют звуком

**iPhone** (`StoryItemSetContainerComponent.swift`; `patches/ios/0006`). Сценарий «сториз →
профиль автора → его другие сториз» запускал звук прежней ленты под новой. Апстрим ставил
ленту на паузу, только когда поверх неё открыт экран определённого типа, а другая лента
сториз в этот список не входила. Теперь лента стоит на паузе под любым экраном.

## Чего изменения не делают

Ни одна правка не добавляет сетевых обращений к чужим серверам, не меняет шифрование и не
собирает статистику. Суммарно это около двух тысяч строк: полторы тысячи на Windows (из них
почти девятьсот приходятся на пересылку копией) и семьсот на iPhone, сотня из которых
описание набора иконок. `git diff` против тега апстрима читается за вечер.
